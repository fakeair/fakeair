# 巡音流歌 · 角色画廊

一个专门展示**巡音流歌（巡音ルカ / Megurine Luka）**角色图片的画廊站。
零依赖、零构建、零追踪脚本 —— 只有 HTML + CSS + 原生 JS。

## 当前画廊里有什么

`assets/works/` 里已有 **10 张图片**（8 张立绘 + 2 张照片类二创），已接入并显示。
页面打开就是：

- 首屏**角色看板**：一张大图主视觉 + 角色简介 + 收录统计（可「换一张主视觉」）
- 下方**全部图片**：10 张缩略图网格，点任意一张进入**全屏看原图**（`←` `→` 翻页、`Esc` 关闭）

## 互动功能（点赞 / 收藏 / 评分 / 短评）

已经做好，开箱即用，**不需要任何配置**：

| 功能 | 位置 |
| --- | --- |
| 点赞 ♥ | 每张图下方的互动条，再点一次取消 |
| 收藏 ★ | 同上；顶部「♥ 我的收藏」可只看收藏的图 |
| 五星评分 | 点开大图后，右侧评分区；再点同一颗星取消 |
| 文字短评 | 大图右侧，可填昵称（会记住），最多 200 字 |
| 排序 | 最新加入 / 最多点赞 / 评分最高 / 评论最多 |

## 加图 / 换图：三步

```bash
# 1) 把图片丢进 assets/works/（png / jpg / webp / gif 都行）
# 2) 生成三档尺寸（列表小图 + 主视觉中图）
node tools/make-thumbs.mjs
# 3) 扫描：读尺寸 + 自动分类 + 自动排序 + 写数据
node tools/scan-works.mjs
```

刷新页面即可。只想加图不想生成小图也行，第 2 步可以跳过
（那样列表会直接加载原图，能看，只是慢）。

### 可选：顺便压一下原图体积

AI 生成的 PNG 动辄 4~5MB。这条命令**不缩尺寸**，只把 PNG 重新编码成 WebP/JPEG，
体积通常能降到 1/5：

```bash
node tools/optimize-originals.mjs
```

实测：10 张原图 **43.8MB → 4.7MB（省 89%）**，1728×2304 分辨率保持不变。
（带透明通道的 PNG 会被自动跳过，避免透明区域变黑。）

### 为什么有第 2 步

原图 4~5MB，10 张就是 44MB，列表会很卡。所以每张原图生成两档 JPEG：

| 用途 | 文件 | 尺寸 | 体积 |
| --- | --- | --- | --- |
| 列表缩略图 | `assets/thumbnails/*.jpg` | 520px 宽 | 约 60~90KB |
| 首屏主视觉 | `assets/hero/*.jpg` | 1000px 宽 | 约 200~400KB |
| 全屏大图 | `assets/works/` 原图 | 原始尺寸 | 压缩后约 400~600KB |

结果：列表只用 **0.76MB**，全站图片合计 **7.9MB**，原图只在点开时才加载。

> 第 2 步需要本机有 Chrome 或 Edge（它借浏览器的 canvas 缩放，不装任何依赖）。
> 找不到浏览器时会自动跳过，画廊回退成加载原图。

### 自动分类规则

扫描器读每张图的**真实宽高**，按宽高比归类：

| 宽高比 | 分类 | 适合 |
| --- | --- | --- |
| ≤ 0.78 | 立绘 | 全身立绘 |
| ≤ 0.95 | 半身 | 半身像 |
| ≤ 1.25 | 头像 | 头像 / 徽章 |
| > 1.25 | 横图 | 场景图 / 壁纸 |

按文件修改时间从新到旧排列（刚放进去的排最前）。
改了作品名 / 作者后再次扫描**会保留**你填的内容；想按新规则重刷分类就加 `--retag`：

```bash
node tools/scan-works.mjs --retag     # 重刷分类，保留标题作者
node tools/scan-works.mjs --reset     # 全部重来，丢掉手改内容
```

扫描产出长什么样，可以看 `data/works.example.js`。

## 一个实现上的取舍（值得知道）

图片的入场动画**只动 transform，不动 opacity**。
因为只要用透明度做「未加载 → 加载完」的切换，一旦动画时钟被暂停
（无头截图、后台标签页、部分省电模式），图就会永远停在透明的第一帧，
表现就是**白板**。这个坑在开发过程中真实踩到过，所以现在基础样式里图片永远可见，
动画只是额外的位移效果，最坏情况也只是位置偏一点。

**主视觉两级加载：缩略图先显示，大图靠 `fetch` + blob URL 替换。**
主视觉大图约 251KB，等它下载完再显示会有明显停顿。现在先用列表已缓存的
缩略图（约 78KB）立刻显示，后台再下大图替换。

替换特意**不用 `<img>` 的 load 事件**：同一张图如果已被别的 Image 请求过
（例如相邻预热），浏览器会复用那次请求，新 Image 的 `load` 可能永远不触发
—— 实测就卡在这里，大图明明下完了却不替换。改成 `fetch` 拿 blob、转成
blob URL 交给 `img`，数据已在内存里，替换必然瞬时完成。

**另一个坑**：不要用隐藏的 `<img>` 去「预热」另一张 `<img>` 正在加载的同一 URL。
浏览器视其为同一资源，隐藏那个的加载被推迟时，会把主图的请求一起取消。

## 关于图片来源

这个站是**展示容器**，不含任何从图站抓取图片的功能。请放入你有权使用的图片：

- 自己画的 / 自己生成或拍摄的
- 获得作者许可转载的同人作品（在 `author` 里署名，有原帖就填 `link`）
- 官方公开的角色素材（[piapro](https://piapro.jp/license/character_guideline) 的角色使用准则允许创作，
  但**把他人作品公开传播需要作者许可**，请注意区分）

`assets/samples/` 里的 12 张示例插画只是占位，可整批删除；
需要重新生成就执行 `node tools/make-samples.mjs`。
